# Panel de administración Encuentrame

El cambio añade un panel de administración completo bajo `/admin`: middleware de guarda, siete server actions con verificación de rol, cuatro páginas (dashboard, negocios, usuarios, categorías) y dos componentes cliente de acción. El enfoque centraliza la verificación de rol en un helper `getAdminUser()` compartido por todas las actions, y replica el mismo check en el layout para asegurar que no hay superficie sin proteger. **Watch for:** los botones de acción revierten el estado optimista en error pero no notifican al usuario (confirmado); las operaciones de toggle usan SELECT + UPDATE en dos pasos, lo cual abre una ventana de race condition pequeña (confirmado); el sidebar desaparece en móvil sin alternativa de navegación (confirmado).

**Verdict**: APPROVED

---

## High-level view

El middleware intercepta `/admin/*` y consulta `profiles` para verificar el rol antes de pasar la request. El layout `AdminLayout` repite el mismo check. La redundancia cierra el caso en que el matcher del middleware se bypasea (Server Actions invocadas directamente, por ejemplo).

Todas las server actions comparten `getAdminUser()`, que retorna `{ error: 'No autorizado' }` si el usuario no existe o no tiene rol admin. Si la política RLS de `profiles` impidiera la lectura, `profile?.role` sería `undefined` y la comparación `!== 'admin'` redirige igual — el comportamiento es fail-closed.

Las mutaciones de toggle requieren SELECT + UPDATE separados porque Supabase JS no soporta `NOT col` en línea. Esto deja una ventana de race condition si dos admins actúan sobre el mismo negocio a la vez. El riesgo es bajo para este volumen de uso pero está presente.

`ToggleBusinessButton` y `ChangeRoleButton` implementan optimistic UI con reversión al error, pero cuando la action falla, el botón revierte silenciosamente sin mostrar ningún mensaje — el usuario no sabe si su acción tuvo efecto.

<details>
<summary>Issues (3)</summary>

1. **Error silencioso en botones de acción** — Cuando `toggleBusinessActive`, `toggleBusinessVerified` o `changeUserRole` retornan `{ error }`, los componentes revierten el estado optimista pero no muestran ningún mensaje al usuario. Añadir un estado de error local y renderizar un toast o texto de error junto al botón.

2. **Race condition en toggle de dos pasos** — `toggleBusinessActive` y `toggleBusinessVerified` hacen SELECT + UPDATE en dos round-trips separados. Si dos admins actúan sobre el mismo negocio simultáneamente, el segundo UPDATE puede sobrescribir el resultado del primero en la dirección equivocada. Se puede eliminar con una función RPC en Supabase: `UPDATE businesses SET is_active = NOT is_active WHERE id = $1`.

3. **Sidebar oculto en móvil sin alternativa** — El sidebar usa `hidden md:flex` sin menú hamburguesa ni drawer. El panel no es navegable en pantallas pequeñas.

</details>

<details>
<summary>Details</summary>

### Error silencioso en botones de acción

`ToggleBusinessButton` y `ChangeRoleButton` detectan el error con `if (result && 'error' in result)` y llaman a `setOptimistic` para revertir, pero no setean ningún estado de error visible. La UI regresa silenciosamente a su estado anterior. Esto es especialmente confuso en errores de red o de permisos — el admin no tiene señal de que su acción no tuvo efecto.

### Race condition en flip de dos pasos

```
SELECT is_active FROM businesses WHERE id = $1   -- lee false
                                                   -- otro admin lee false también
UPDATE businesses SET is_active = true             -- primer admin pone true
UPDATE businesses SET is_active = true             -- segundo admin pone true también (debería poner false)
```

Ambas actions leen el valor antes de que el otro escriba, y ambas calculan el nuevo valor como `!false = true`. El resultado final no refleja la intención del segundo admin. Una función RPC que ejecute el flip dentro de la transacción elimina la ventana.

### Sidebar sin acceso móvil

`hidden md:flex` es la clase en el `<aside>`. No existe ningún elemento de navegación alternativo para viewport < `md`. Como panel de admin de uso interno es deuda técnica aceptable a corto plazo, pero debe documentarse como limitación conocida.

</details>
